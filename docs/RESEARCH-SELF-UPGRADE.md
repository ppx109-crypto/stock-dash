# 연구가 스스로 나아지는 방식(사용자 2026-10-15 "점점 업그레이드되는 방향의 알고리즘으로 · 더 알아서 잘 하고 더 똑똑해지는 방향으로")

한 번 잡힌 실수는 다시 나오지 않게 **점검표 · 도구 · 시험**으로 바꿔 둡니다. 회차가 쌓일수록 GPT가 '고칠 것'으로 돌려보내는 횟수가 줄어야 합니다.

## 1. 도는 순서(회차마다)
1. **읽기**: 사전등록을 쓰기 전에 이 문서 §2 점검표와 §4 실패 지도를 읽음.
2. **재현 먼저**: 바탕(지금 운영 판)을 같은 코드 · 같은 자료로 다시 돌려 지문(sha256)이 바이트까지 같은지 확인한 뒤에만 새 것을 붙임.
3. **순수 셈 + 합성 시험**: 새 규칙은 자료를 받지 않는 순수 함수로 짜고, 작은 가짜 자료로 순서 · 한도 · 미래 참조 시험을 먼저 통과.
4. **영수증 사슬**: verify → test → build → bases → cut → run. 앞 단계 영수증이 없거나 · 다른 코드 지문이거나 · FAIL이거나 · 결과 파일이 바뀌면 다음 단계가 멈춤.
5. **GPT 검토 뒤**: 지적마다 사실(파일 · 줄 · 수치)로 확인 → 맞으면 고치고 **§2에 한 줄 더함**(가능하면 자동 검사로) · 틀리면 근거로 반박.
6. **결과 뒤**: §4 실패 지도에 '무엇을 · 왜 안 됐나 · 다음에 피할 것'을 한 줄 더함. §3 성적표 갱신.

**조치(코드 · `research/rxkit.py` · 시험 `tests/test_rxkit.py` 5개)**
1. `dry()` 마른 실행: 모든 단계 일감(명령 · 환경)을 먼저 다 만들어 보고, 단계마다 smoke 일감 하나를 짧게 실제로 돌린 뒤에만 본 셈. → 이번 실행 오류는 첫 1분에 잡힘.
2. `stage_code()` 단계별 영수증: 그 단계가 쓰는 파일만 지문으로 묶고 결과 파일 지문은 그대로 검사. → 판정 코드 한 줄 고침에 장부를 다시 만들지 않음.
3. `run_dag()`: 앞 일감이 끝난 것부터 바로 다음 일감 · 일꾼 = CPU 수. → 자르기 장부를 계좌 셈과 나란히.
4. `lint()`: `값 or 숫자`(0을 결측처럼) · `dict(**X, KEY=…)`(중복 열쇠 실행 오류) 꼴을 찾음 — 지난 코드에 돌리면 이번 두 실수를 모두 잡음(확인함).
5. `review_prompt()`: 사전등록을 내기 전에 대리 검토자(하위 에이전트)에게 점검표로 반대 검토를 시킴 → 결함을 고친 뒤에 GPT에게 냄.
