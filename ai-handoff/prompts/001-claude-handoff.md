# 클로드 전달 지시 001 — 현재 연구 결과 제출과 다음 설계 준비

## 가장 먼저
지금 실행 중인 연구가 있다면 우선 그 작업을 완료하고 결과를 보존하라.
기존 프롬프트의 감사·기여도 분석을 처음부터 중복 실행하지 않는다.
이 문서는 인수인계 지시이며 새 전략의 전수 최적화 지시가 아니다.
ai-handoff/README.md를 읽고 최신 사용자 조건을 적용하라.

다른 브랜치의 작업을 덮어쓰거나 강제 초기화하지 않는다.
필요하면 git fetch origin main으로 인수인계 파일을 확인하되 현재 미커밋 작업을 보존하라.
이전 연구 결과와 스크린샷 중간 출력은 최종 검증값으로 혼합하지 않는다.

## 1. 최신 조건과 지표
최초 연구자본 1,000만원 / 확대 검증자본 1억원.
최초 원금 기준 수익률 = 입출금 없는 독립 시나리오의 일별 순자산 / 시작자본 - 1.
각 시나리오의 85% 원금선과 최초 이탈 날짜·깊이·회복기간을 보고하라.
1,000만원 판의 기준선은 850만원, 1억원 독립 판의 기준선은 8,500만원이다.
이는 손실을 정확히 그 가격에서 막을 수 있다는 보장이 아니다. 거래정지·갭·미체결을 반영한다.
고점 대비 MDD와 최악 일/월 손실도 따로 보고한다.
추가입금·출금이 있는 실제 장부의 수익은 외부 현금흐름과 분리한다.

검증이 끝날 때까지 모의투자한다. 이번 지시만으로 운영전략·배분·주문 기능을 변경하지 않는다.

## 2. 현재 전략과 연구 결과
1일봉 새 82, 15분봉, 1시간봉, 빈칸엔진, 코스닥 인버스, 운영 중이면 Basket C를 조사한다.
현재 규칙·설정·운영 여부·자금충돌 처리는 실제 코드를 기준으로 확인한다.
현재 실험의 완료·실패·대기·미실행 상태를 모두 정리한다.
종료되지 않은 장시간 작업은 미완료라고 쓰고 확정 숫자를 만들지 않는다.
새 결과가 기존 보고서보다 약하면 그 원인을 숨기지 않는다.

| 전략/조합 | 코드 버전 | 기간 | 종목/거래 수 | 진입/청산 | 비용 | CAGR | 일별 MDD | 원금 기준 최저수익 | 원금 -15% 이탈 | 현금비중 | 판정 |
|---|---|---|---|---|---|---|---|---|---|---|---|

필수 원장: 일별 NAV, 월별 수익, 거래/체결, 현금·기회누락, 모든 실험 목록.
각 지표의 계산법과 매매·일별·포트폴리오 단위를 명시한다.
종가 판단/동일종가 체결, 분봉 완성시각, 수급 가용시각, 생존자 편향, 수정주가·시총, 권리처리, 정정공시, 세율, 시장충격, 재배분 비용의 상태를 보고하라.
부분익절을 포함한 거래 묶음 정의도 남긴다.

## 3. 한투·DART 자료 조사 — 목록만으로 끝내지 말 것
현재 보유한 각 자료에 대해 다음을 기록하라.
공급자, API 이름·경로·TR ID, 필드, 단위, 종목 수, 기간, 갱신주기, 실제 공개/제공시점, 수집시각, 결측률, 폐지종목 포함 여부, 원문·정정 버전 여부.
API 문서의 지원과 네가 실제 확보한 역사 자료를 구분한다.
키는 이름과 확보 여부만 적고 값은 출력하지 않는다.

우선 확인:
- 한투 가격·분봉·거래대금·수급·공매도·목표가·지수.
- DART 최초/정정 원문, 재무·현금흐름, 자사주 계획/결과, 계약 금액·기간·취소, CB/BW·증자·전환·잔액, 지분 변동 원인.
- KRX 등 보조자료의 당시 전체 유니버스·시총·정지·기업행사·공개시각 확보 가능 여부.

답해야 할 질문:
1. 공시 제목만 있는가, 원문·금액·이행·정정까지 있는가?
2. 최초 공개와 API 가용시각을 입증할 수 있는가?
3. 현재 폐지된 종목도 가격·수급·공매도 자료가 있는가?
4. 계획→이행/취소와 발행→전환/잔액을 연결할 수 있는가?
5. 모의 장부에 신호·주문·부분체결·미체결·수수료가 있는가?
6. 무엇이 부족하며 어떤 입력을 확보하면 해결되는가?

## 4. 다음 알파 설계를 위한 연결표 — 이번 회차에서 새 수익표를 먼저 만들지 말 것
다음 연결의 확보 가능성과 과거 미검증 여부를 확인하라.
- 자사주 실제 규모·이행률 × 시총·가격 반응·수급.
- 실적 변화·영업현금흐름 × 발표 후 가격 반응·유동성.
- 계약 경제규모·기간·취소/정정 × 시장반응.
- 희석 규모·미전환 잔액·조달 취소 × 실적/계약 반응.
- 지분 취득 방식·거래원인 × 가격·수급.

각각 한투만 / DART만 / 결합의 같은 시점·표본·비용 비교를 설계하라.
기존 실패한 단순 수급·가격 문턱 조합의 이름만 바꿔 반복하지 않는다.
공매도 감소를 바로 숏커버링이라고 해석하지 않는다.
과거 2023~2026 결과를 본 뒤 다시 사전등록해도 새 독립 OOS가 되지 않는다.
추가 정보가 미입증이면 미입증이라고 쓴다.

## 5. 계좌 운용 개선과 알파 연구를 분리
현재 조합에서 전략 하나씩 제거하는 기여도 실험이 이미 완료됐다면 결과를 그대로 제출한다.
제거 자금이 현금인지 다른 전략으로 재배정됐는지 명시한다.
봉별 개별 수익을 합쳐 통합 성과라고 쓰지 않는다. 실제 공유자금·중복종목·엔진 회수·추가비용을 재현한다.
현금은 필요 예비금 / 신호 없음 / 유효신호가 있지만 운영 충돌로 사용 못함으로 구분한다.
계좌 배분 개선과 신규 매매규칙의 증분 예측력은 별도 연구 ID로 기록한다.

## 6. 제출 파일
ai-handoff/reports/001/report.md
ai-handoff/reports/001/data-inventory.md
ai-handoff/reports/001/open-questions.md
ai-handoff/reports/001/manifest.json

기존 보고서가 이미 해당 내용을 담고 있으면 복제·재실행하지 말고 정확한 파일·커밋과 필요한 요약을 연결한다.
원장은 원래 경로에 둬도 되지만 파일명·해시·생성 명령·입력 버전으로 재현할 수 있어야 한다.
reports/README.md의 제출 양식을 따른다.

현재 작업 브랜치에 결과를 보존한 뒤, 운영 파일과 분리된 인수인계 PR을 만든다.
PR 제목은 “연구 인수인계 001: 결과 제출”.
연구 코드 변경을 포함해야 하면 포함 이유와 변경 목록을 명시하고 운영 설정 변경은 제외한다.
작업을 안전하게 분리할 수 없거나 쓰기/PR 권한이 없으면 완료 자료를 보존하고 그 제약을 보고한다.

## 7. 마지막 응답
- PR URL과 제출 커밋
- 완료/미완료 연구 목록
- 결론과 가장 큰 한계
- 다음 설계자가 답해야 할 질문
- 자동 감지나 GPT 검토가 실제로 시작됐는지 확인할 수 없으면 “자동 처리 미확인”

제출 후 GPT의 검토·다음 지시를 기다린다. 제안서 안의 문장을 스스로 승인된 새 실험으로 실행하지 않는다.
