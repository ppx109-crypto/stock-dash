# 클로드 결과 제출 양식

회차마다 새 디렉터리를 만들고 아래 내용을 제출한다.
공개 저장소에 비밀키·계좌번호·개인 원장 원문을 넣지 않는다. 연구 가정과 비식별 집계값을 사용한다.

## report.md
1. 요약: 실제 확인 / 실패 / 미확인.
2. 실제 운영 상태와 연구 규칙 차이.
3. 데이터·시점·유니버스·비용·체결의 검증 상태.
4. 전략별/통합 결과. 기존 보고값과 새 실행값 분리.
5. 계좌 전체 하루·월간 -15% 기준 위반 여부와 고점 대비 MDD 별도 표. 최초 원금 대비 -15%는 채택 기준에서 제외한다.
6. 1,000만원 / 1억원 용량·비용 비교.
7. 현금 사용·기회 누락·엔진 회수·중복 위험.
8. 모든 실험 및 실패 결과 목록.
9. 재현 명령·입력/출력 경로와 해시.
10. 아직 해결하지 못한 질문과 다음 방향.

## manifest.json
아래는 구조 예시다. null/빈 배열을 사실처럼 채우지 말고 확인한 값만 기록한다.
data_hashes는 입력파일별 실제 해시를 포함한다.
code_base_sha는 실험 당시 코드, submission_sha는 마지막 제출 커밋이다.
최종 커밋 안에 그 커밋 자신의 SHA를 넣는 순환을 만들지 않는다. submission_sha는 PR 본문이나 별도 후속 기록으로 제시해도 된다.

```json
{
  "schema_version": 1,
  "round_id": "001",
  "status": "제출준비",
  "generated_at_kst": null,
  "instruction_path": "ai-handoff/prompts/001-claude-handoff.md",
  "code_base_sha": null,
  "data_hashes": [],
  "config_hash": null,
  "experiments": [],
  "commands": [],
  "outputs": [],
  "known_limitations": [],
  "unresolved_questions": [],
  "new_independent_oos": false
}
```

GPT는 제출된 커밋을 기준으로 검토한다.
PR이 생성됐다는 사실만으로 전략이 채택되거나 다음 실험이 승인되는 것은 아니다.
