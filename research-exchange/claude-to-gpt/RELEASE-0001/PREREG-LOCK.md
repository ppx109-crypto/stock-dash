- 지시: PR #24 head `3e3f739fd0f385e506aceb6a90ee094d7aa88d1d`. source PR #23 head `b1f1f228d2abb2f41e96cd4f9775aa430dbeca85`.
- 이 문서와 `fixtures/fixtures.json`(만드는 도우미 `fixtures/make_fixtures.py`), `tests/materialize.py`는 **사후 증명 도우미 · 시험 실행기를 쓰기 전에** 결과 가지의 첫 커밋으로 잠급니다.
- 잠그기 전에 본 것: PR #24 파일, PR #23의 사건 목록 시각(본문 내용 아님). GraphQL은 이 세션에서 쓸 수 없어 본문 수정 시각은 확인하지 못했습니다.
- READY의 뜻은 **공개 제출 후 metadata 확인 절차 통과**뿐입니다. 저장소 이력 청정, 실제 전략 검증, `PAPER_VALIDATION_READY`, 실전 승인이 아닙니다.

## 1. 규칙(도우미 `attest.py`, 표준 라이브러리만)
- `scan(text)` = 비공개 세션 주소 모양(대소문자 무시: 호스트 `claude.ai` + `/code/session_` + 영숫자 6자 이상)의 개수 + 그런 주소가 없는 `Claude-Session:` trailer 줄의 개수. 값은 돌려주지 않습니다.
- `correct(body)`
  - 세션 주소가 든 줄이 **footer 줄**(`Generated by`가 들어 있음)이면 그 줄 전체를 `_Generated by Claude Code_`로 바꿉니다.
  - 그 밖의 줄은 바꾸지 않습니다. 본문 중간에 남아 있으면 `correctable=false`입니다.
  - 두 번 적용해도 결과가 같아야 합니다(멱등).
- `evaluate(snapshot)` → status와 코드 목록
  - `POSTCHECK_MISSING`: PR을 연 뒤 GitHub에서 본문을 받지 않음
  - `POSTCHECK_NOT_GITHUB`: 사후 검사 출처가 로컬 파일
  - `PRIVATE_SESSION_METADATA:body` · `:commit`: 실제 본문 · 커밋 메시지에서 개수 > 0
  - `IMMUTABILITY_FAIL:head`: 현재 head ≠ 연 때의 head
  - `IMMUTABILITY_FAIL:commit_after_open`: 커밋 수 > 연 때 커밋 수
  - `COMMENT_NOT_CONFIRMED`: comment receipt를 다시 읽어 찾지 못함
  - 코드가 하나라도 있으면 BLOCKED, 없으면 READY
- `receipt(...)`
  - 키는 정확히 9개입니다: `task_id, result_pr, head_sha, checked_at_kst, body_private_session_count, commit_private_session_count, body_corrected, branch_commit_after_open, status`
  - 키가 더 있으면 `RECEIPT_EXTRA_FIELD`, 값에 세션 주소 모양이 있으면 `RECEIPT_LEAK`
- 출력에는 규칙 코드 · 개수 · SHA만 담고, 매치된 문자열은 절대 담지 않습니다.

## 3. 실제 GitHub 사후 절차(결과 PR을 연 뒤, 결과 가지에는 커밋하지 않음)
1. 열기 전
   - 본문 파일과 `origin/main..HEAD` 커밋 메시지를 `scan`으로 확인합니다(**local_precheck**, 0이어야 함).
   - 연 때의 head SHA와 커밋 수를 적어 둡니다.
2. PR을 연 뒤 **github_postcheck**를 여러 번 합니다(약 30초 · 2분 · 4분 · 6분 · 8분). 매번 GitHub에서 같은 PR의 본문 · head · 커밋 메시지를 받아 `evaluate`합니다.
3. 어느 회차에서든 본문 개수 > 0이고 `correctable`이면, **그때 받은 실제 본문**에 `correct`를 적용해 PR 본문 metadata만 1회 보정합니다. 그 뒤 30초 · 3분에 다시 받습니다.
   - 보정은 1회뿐입니다. 다시 생기거나 보정할 수 없으면 반복하지 않고 BLOCKED입니다.
4. 마지막 확인 결과로 9키 receipt comment를 올립니다. 마지막 줄에는 세션 없는 일반 표기를 붙입니다.
   - 올린 뒤 30초 · 2분에 comment와 본문을 다시 받아 확인합니다.
   - comment 자체에 자동 세션 footer가 붙으면 그 comment의 footer만 1회 보정하고 재확인합니다(사전등록한 예외).
   - 확인에 실패하면 status BLOCKED comment를 남기고 숨기지 않습니다.
5. 알려진 한계: footer가 제 확인 창(대략 PR 연 뒤 12분) 뒤에 붙으면 잡지 못합니다. 이 경우를 REPORT와 채팅에 밝힙니다.
