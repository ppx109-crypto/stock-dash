## 1. 규칙(고정)
- **접수일 d의 주식수는 d보다 큰 첫 거래일 t부터 씀.** 코드: `known_next(종목, 날)` = 접수일 **<** 날인 보고 가운데 마지막(지금 `caps.known_by`는 접수일 ≤ 날).
  - 판단하는 날은 언제나 가격 행이 있는 거래일이므로 '접수일 < 날'과 'd보다 큰 첫 거래일 ≤ 날'은 같음(날이 거래일이고 d < 날이면 d 뒤 첫 거래일 t ≤ 날 · 거꾸로 t ≤ 날이면 d < t ≤ 날). 따로 달력이 필요 없음.
- **휴장일 · 주말 접수**: 위 규칙대로 그 뒤 첫 거래일부터.
- **장 마감 뒤 접수**: share-data에는 접수 날짜만 있고 시각이 없음 → 모든 접수를 장 마감 뒤로 봄(보수). 장 시작 전 접수도 하루 늦게 씀(놓치는 쪽 · 앞당기는 쪽 아님).
- **같은 날짜 여러 보고**: 고정 엔진 규칙 그대로 둠 — `caps.raw_timeline`이 (날, 주식수)로 정렬하므로 같은 날 가운데 마지막 = **가장 큰 주식수**. 접수 순서가 아님을 밝히고, 그런 날 수 · 값이 서로 다른 날 수를 셈. 이번에 바꾸지 않음.
- **정정 보고서**: share-data에 정정 표시 · 원 보고 연결이 없음. 정정이 자기 접수일의 다른 줄로 들어 있으면 그 다음 거래일부터 씀. 수집기가 원 보고를 정정 값으로 덮어썼다면 복구 못 함 → share-data 파일 git 판끼리 같은 접수일 값이 바뀐 흔적을 셈(감사 A와 같은 방식). 흔적 0이어도 PIT_OK로 보지 않음.
- **처음 주식수 없음**: `known_next`가 None → 순위 없음 → inside 아님('모름'이지 '바깥' 아님 · 지금과 같음). 첫 보고 접수 당일 행이 새로 '모름'이 되는 건수를 셈.
- **0 · 빈 값**: `raw_timeline`이 이미 뺌(그대로).
- **CAPS_ADJ = 0 고정**(고정 엔진 · 원 장부 z055_d1_raw · 정직 캐시 판 2와 같은 원 주식수). 실행 때 환경값이 0이 아니면 멈추고, 영수증에 적음.
  - 남는 결함(이번에 안 풀림): 가격은 study.load_prices의 **수정주가**, 주식수는 **그때 주식수**라 쪼개기 · 무상증자 앞 시총이 작게 나옴(AUDIT-1 F1 · 삼성전자 2017 ~ 19 약 1/50). 날짜를 늦추는 것만으로 단위 정합성 · 원자료 vintage는 해결되지 않음.
  - `CAPS_ADJ=1`(adjusted_timeline)은 전체 보고의 가운데값 · 대차 자료 원주가로 배수를 만들어 따로 감사가 필요 → 이번 범위 밖.
