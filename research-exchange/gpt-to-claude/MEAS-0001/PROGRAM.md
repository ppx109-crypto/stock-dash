# 모의검증 준비까지 연구를 이어가는 설계
사용자의 최신 지시: 현재 모의투자 신뢰성을 감사하고, 유효하면 규칙을 강화하며, 핵심 결함이면 새 규칙을 설계해 모의검증 가능한 단계까지 진행한다.
기존 3라운드 후 매번 승인 대기는 이 연구 프로그램에 한해 대체한다. 자동 지속은 증거에 따라 다음 단계 한 건을 발행한다는 뜻이며 수익 보장/무제한 최적화/운영 변경 승인이 아니다.
기존 RULES 체인은 종료 이력을 보존하고 새 MEAS/REPLAY/ALPHA/SHADOW task_id로 진행한다.

## 고정 목표·금지
- 낙폭, 비용 후 기대값, 자금 활용을 함께 평가. 무조건 전액 투자하지 않는다.
- 계좌 하루/달력월 손실 각각 −15%, 고점 대비 일별 MTM MDD −15%는 독립 기준. 입출금을 보정한 TWR와 계좌 NAV를 구분한다.
- 모의검증 종료 후 1천만원 약6개월→1억원 계획은 용량 시나리오. 자동 실전 전환/증액 승인 아님.
- 실계좌/API 실주문, 계좌 인증 변경, 운영 봇 재시작·전략·배분·워크플로 수정, 자동병합 금지.
- 현재 모의 봇을 그대로 두고 연구 복사본/오프라인/별도 shadow만 허용. API 모의주문 실행도 준비 판정과 별개이며 이번 프로그램의 자동 실행 권한에 포함하지 않는다.
- 모의 파생 성과/비식별 기록 공개는 허용. 키/토큰/계좌번호/원본 계좌 응답/실계좌 자료/비공개 세션 주소 공개 금지.
- 기존 동일 Claude 세션에서만 진행. 새 세션/탭/Routine 및 중지된 Routine 재활성화 금지.

## 단계와 전환 근거
| 단계 | 작업 | 다음 단계로 넘기는 증거 |
|---|---|---|
| MEAS-1 | 기존 모의 원장, 현금·보유·체결·수급시각, 캐시 생성 출처, 비용/MTM 측정 감사 | 실제로 있는 기록과 결손 구분, 대사 결과, 시점 사용 위반 목록, 수정할 측정 계약 |
| REPLAY-1 | 확인된 측정/시점 결함만 연구 복사본에서 수정하여 고정 규칙 재생 | 원본 vs 수정 비교·의미 변경 목록·기존기간 진단 표시·자금/주식 보존 검산 |
| BASELINE-1 | 생존자·정정·가용시점·실행 가격·비용 후 기존 규칙의 재현성 평가 | 유효/실패/미확인 분류와 충분성, 기존에 본 기간을 OOS로 부르지 않음 |
| ALPHA-1 | 유효 규칙이면 독립 기여를 검사해 개선; 실패 규칙이면 새로운 정보 가설로 대체 설계 | Train-only 사전등록, 모든 실험 공개, 단독 KIS/단독 DART/결합 ablation, 목표별 tradeoff |
| VALIDATE-1 | Validation→LOCK→미사용 OOS/walk-forward 및 체결·용량 스트레스 | 새 OOS 근거/실험 수/cluster·block CI/비용/일·월·MDD/1천만·1억원 시나리오 |
| SHADOW-1 | 검증된 규칙의 모의 실행 계약·리플레이/가상 체결 검증 | 신호/주문 의도/체결/비용/NAV 대사·중복 방지·결손 시 신규 진입 차단·관측 계획 |
| PAPER_VALIDATION_READY | 후보·규칙·모의 측정 방법이 준비됐다는 판정 | 현재 봇 변경/새 API 주문/실전 승인이 아님. 실측 검증은 별도 보고 |

각 단계는 다음 단계를 한 번에 모두 구현하라는 명령이 아니다. 이번 실행 TASK는 MEAS-1만이다.
측정 계약의 미래정보/가상 현금 누수부터 제거한다. 좋은 수익률을 얻기 위해 측정 오류를 그대로 두지 않는다.
기존 규칙을 재면 실패했다는 것과 측정이 불가능하다는 것을 구분한다. 미확인 전략을 알파가 없다고 폐기하지 않는다.
OOS가 이미 소비됐거나 미래 표본을 기다려야 하면 관측 계획을 고정하고 WAITING_DATA로 보고한다. OOS 날짜를 바꾸면서 자동 재시험하지 않는다.

## 연구·선택 통제
- 모든 비교의 code/data/hash/Universe(t)/available_at/정보 cutoff/진입·청산/비용/노출/자금 규모를 사전 고정한다.
- 새 전략·threshold 탐색은 감사 전 금지. ALPHA 단계에서만 Train 내부 사전등록된 유한 실험 예산과 탐색 공간을 정하고 Validation/OOS 전에 잠근다. GPT가 개별 TASK에서 허용한 실험만 수행한다.
- 이미 실패한 RSI/단순 수급/단순 공시 조합의 이름·숫자만 바꾸어 재연구하지 않는다. 새로운 이벤트×시장반응의 독립 정보 가설이 있어야 한다.
- 새 규칙은 유명지표 조합이나 높은 CAGR을 이유로 선택하지 않는다. 비용 후 기대값, MDD/월 손실, 상관·용량·현금 활용을 함께 보고한다.
- 채택 기준·최소표본·CI 방법·다중시험 보정은 OOS 결과 전에 별도 사전등록한다. 표본 부족/CI 미확정은 미확인이다. 사용자 위험 기준을 완화해 통과시키지 않는다.
- 기존 기간 진단으로 긍정 결과가 나와도 PAPER_VALIDATION_READY 판정을 하지 않는다.

## 자동 진행·정체 처리
한 번에 실행 TASK 하나, 완료 READY/BLOCKED 결과 하나, GPT 근거 감사 후 다음 TASK 하나. 결과가 공식 완료되기 전 새 작업을 발행하지 않는다.
고정 3회 숫자로 사용자의 승인을 반복 요청하지 않는다. 대신 TASK별 종료조건과 진척 증거를 기록한다.
BLOCKED에서 원인이 기존 자료로 해결 가능하면 같은 실패를 반복하지 않고 독립적인 한 단계 복구 TASK를 발행할 수 있다.
필수 자료/권한/유료 자료가 없으면 NEEDS_DATA 또는 NEEDS_USER로 구체적으로 보고한다. 추정치로 채우거나 사용자가 답하지 않았는데 권한을 늘리지 않는다.
새 근거 없이 같은 실패를 반복하는 작업·미사용 OOS 없이 threshold 재탐색·무한 수익률 탐색은 중단한다. 웹훅 수신은 계속 활성화한다.
준비 판정 후 자동 연구 확장을 멈추고 모의검증 계획/한계/사용자 다음 결정을 보고한다.
