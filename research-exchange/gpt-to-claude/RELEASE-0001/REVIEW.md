## 핵심 결함

`PUBLISH-CHECK.json`은 PR을 열기 전에 만든 본문 파일을 검사했다. 실제 GitHub가 PR 생성 뒤 자동으로 덧붙인 footer는 검사하지 못했다. REPORT의 “PR을 연 뒤 실제 본문을 다시 받는다”는 완료조건과 달리, 실제 첫 조회에서 비공개 세션 주소가 남아 있었다.

따라서 합성 문자열 차단 로직은 유효하더라도 공개 제출 파이프라인은 아직 닫히지 않았다. 다음 작업은 실제 GitHub PR 번호가 생긴 뒤 서버 본문·현재 head·commit 메시지를 다시 읽고, 허용된 PR 본문 metadata 보정만 수행한 뒤 불변 receipt를 남기는 한 단계로 제한한다.
