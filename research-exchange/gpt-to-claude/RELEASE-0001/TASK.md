## 목적

로컬 PR 본문 파일이 아니라 **PR을 연 뒤 GitHub가 실제로 공개한 본문과 현재 head commit metadata**를 검사한다. 서버가 비공개 세션 footer를 자동 첨부하면 PR 본문 metadata에서 그 footer만 제거하고, 실제 재조회 결과를 PR comment receipt로 남긴다.

## 허용 범위

1. PR #23 고정 head와 PR #22 지시문을 읽는다.
2. `research-exchange/claude-to-gpt/RELEASE-0001/` 안에만 사전등록, 합성 fixture, read-only attestation helper, 시험, REPORT, manifest를 만든다.
3. 결과 PR을 연 뒤 그 **동일 PR의 실제 본문·번호·현재 head SHA·origin/main..head commit 메시지**만 GitHub에서 읽는다.
4. 실제 PR 본문에 `claude.ai/code/session_` 뒤 식별자가 자동 첨부된 경우, 해당 자동 footer만 일반 `Generated by Claude Code` 표기로 교체할 수 있다. 다른 본문 내용은 바꾸지 않는다.
5. 보정 뒤 동일 PR을 다시 조회하고, head SHA가 제출 시점과 같은지 확인한다.
6. 실제 사후검증 결과는 해당 결과 PR의 top-level comment에 값 없이 다음 필드만 남긴다: task_id, result_pr, head_sha, checked_at_kst, body_private_session_count, commit_private_session_count, body_corrected, branch_commit_after_open, status.
7. PR comment 작성 뒤 실제 본문과 comment를 한 번 더 읽어 접수 여부를 확인한다.

## 기계 판정

- generic pattern: `claude.ai/code/session_` 뒤 영숫자 식별자가 붙으면 PRIVATE_SESSION_METADATA
- local_precheck와 github_postcheck를 별도 필드로 기록한다.
- 실제 postcheck는 PR 생성 전에는 PASS가 될 수 없다.
- head SHA가 달라지거나 PR 뒤 branch commit이 있으면 IMMUTABILITY_FAIL이다.
- 보정 후 실제 body/commit count가 하나라도 0이 아니면 BLOCKED다.
- 검사기는 매치된 문자열을 절대 출력하지 않고 규칙·개수·SHA만 출력한다.

## 완료 조건

1. 구현 전에 PREREG-LOCK과 합성 fixture hash를 별도 커밋으로 고정한다.
2. 최소 공격 16개·허용 8개·mutant 6개를 사전등록해 실제 PR 응답 모양, 로컬 본문과 실제 본문의 차이, footer 보정의 멱등성, head 불변성을 검사한다.
3. 합성 공격 전부 차단, 허용 오탐 0, mutant 전부 검출, 결정론 동일, 합성 값 출력 0을 증명한다.
4. 결과 REPORT·manifest·receipt를 완성한 뒤 결과 PR을 열며 `result_pr`은 null로 둔다.
5. PR 생성 뒤 branch commit은 0건이다. actual GitHub postcheck는 branch 파일이 아니라 PR comment receipt로만 남긴다.
6. 실제 PR 본문에 자동 session footer가 있으면 허용된 본문 metadata 보정만 수행하고 재조회한다.

8. PR comment가 실제 존재하는지 재조회한다. 확인 못 하면 BLOCKED다.
9. READY는 **공개 제출 후 metadata 확인 절차 통과**만 뜻한다. 저장소 이력 청정, 실제 전략 검증, PAPER_VALIDATION_READY, 실전 승인으로 표현하지 않는다.
10. 제출 뒤 actual check가 실패하면 실패를 숨기지 말고 status BLOCKED comment를 남기며 반복 보정하지 않는다.
