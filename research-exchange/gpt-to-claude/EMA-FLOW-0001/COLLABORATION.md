# 공동 연구 방식 — 사용자 2026-10-08 17:05 KST 정정

사용자의 EMA/수급 조합은 고정 정답이나 반드시 채택할 지시가 아니라, GPT와 Claude가 스스로 조합 가설을 만들고 계산·반박·개선하라는 예시다. 이 예시만 고집하거나 사용자가 매번 아이디어를 내기를 기다리지 않는다.

현재 EMA-FLOW 네 판은 이 예시를 다루는 한 번의 유한 실험으로 유지하되, 효과가 없으면 종료한다. 결과에 맞춰 숫자를 계속 바꾸거나 반복 문서 검증을 하지 않는다. 후속 가설은 새 근거가 있을 때 각자가 제안하고 한정 배치를 계산 전에 고정한다. 기존 실패 가설 목록을 확인해 이름/숫자만 바꾸어 반복하지 않는다.

Claude는 새 규칙 배치를 직접 계산하고 구현상 위험/성과 반박을 제출한다. GPT도 가능할 때 동일 자료의 별도 연구 사본에서 직접 계산하고 최초 차이/추가정보/비용 민감도를 확인한다. 단순 지표 산술, 같은 공유 엔진 재실행, 독립 구현을 구분한다. GPT가 실제 실행하지 못한 부분을 직접 계산했다고 쓰지 않는다. 중간 검증요청 문서 교환 대신 코드/수치가 있는 한 묶음 결과에서 비교·종료·다음 방향을 정한다.

여기서 RL은 사용자 의도상 결과 피드백으로 공동 개선하는 방식이다. 실제 강화학습 에이전트의 state/action/reward 학습을 구현하지 않았다면 RL 모델 학습 성과로 표현하지 않는다.

최신 목적은 비용후 복리 개선이며 운영/주문/인증/레버리지/비밀/자동병합 권한을 확대하지 않는다. 이미 본 기간을 미사용 OOS로 재명명하거나 성과를 보장하지 않는다. 모르는 필수 데이터는 정확히 한 번 보고하고, 근거 없이 같은 실패를 반복하지 않는다.
